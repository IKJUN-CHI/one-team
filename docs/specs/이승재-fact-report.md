# 사실 중심 리포트 전송 (fact-report)

- 작성자: 이승재
- 날짜: 2026-10-29
- 제품: 집사이 (집 관리 플랫폼)

## 연결된 WhyTree 노드

`docs/whytree/이승재.md`의 씨앗 "사실 중심 리포트 전송"

- 주요 why: 상대에게 정확히 전달하기 → 집 문제 빨리 해결하기
- 부가 why (점선): 합의 내용 믿기 → 보증금·수리비 다툼 줄이기

## 누구를 위한 기능인가

- **사용자:** 집에 사는 임차인
- **받는 사람:** 임대인
- **문제가 생기는 순간:** 거주 중에 고장이나 하자(누수, 보일러 고장, 곰팡이 등)를 발견해 임대인에게 수리를 요청해야 할 때. 이때 임차인은 당황하거나 화가 난 상태라서, 카톡으로 보내는 메시지에 감정, 원인 추정, 책임 주장이 섞이기 쉽다. 받는 임대인은 무엇이 언제부터 어떻게 문제인지 파악하기 어렵고, 방어적으로 반응하기 쉽다.

## 사용자가 하는 일

1. 임차인이 문제 상황을 자유롭게 글로 쓴다. 말투나 형식은 신경 쓰지 않아도 된다.
2. 사진을 1~3장 첨부한다.
3. "정리하기"를 누르면 AI가 글을 아래 항목으로 정리한다. 이때 감정 표현, 원인 추정, 책임 주장은 뺀다.
4. 확인 화면에서 정리된 항목을 읽고 필요한 칸을 고친다. "미입력"으로 남은 칸을 채운다.
5. "보내기"를 누르면 리포트가 확정되고 공유 링크가 생긴다.
6. 링크를 복사해 카톡이나 문자로 임대인에게 보낸다.
7. 임대인은 링크를 열어 로그인 없이 리포트를 본다.

## 리포트 항목

| 항목 | 내용 | 예시 |
|---|---|---|
| 위치 | 문제가 있는 곳 | 욕실 천장 |
| 증상 | 관찰한 사실만 | 천장에서 물이 떨어짐, 얼룩이 생김 |
| 처음 발견한 날짜 | 원문에 나온 그대로 | 지난주 화요일 |
| 현재 영향 | 생활에 미치는 영향 | 욕실 사용이 불편함 |
| 요청 사항 | 임대인에게 바라는 것 | 수리 일정 조율 요청 |
| 사진 | 임차인이 첨부한 원본 | (이미지 1~3장) |

- 넣지 않는 것: 원인 추정("윗집 때문 같다"), 책임 소재("집주인이 관리를 안 해서"), 비용 부담 주장
- 원문에 없는 정보는 추측하지 않고 "미입력"으로 둔다.

## 우선순위

### P0 — 반드시

- 자유 입력 글 작성 화면
- 사진 1~3장 첨부. 원본 그대로 저장하고 보여주며, AI에게는 보내지 않는다.
- AI 정리: 글을 6개 항목 중 사진을 뺀 5개 항목의 JSON으로 정리한다.
- AI 실패 처리 (아래 "AI 모델" 참고)
- 확인 화면: 모든 항목을 수정할 수 있다.
- 보내기: 리포트를 확정하고, 보낸 날짜와 시각을 기록하며, 공유 링크를 만든다.
- 링크 복사 버튼
- 공유 링크 페이지: 로그인 없이 볼 수 있다. 항목, 사진, 보낸 시각이 보이고, 수정할 수 없다.
- 로컬 저장: 리포트는 JSON 파일에, 사진은 `uploads/` 폴더에 저장한다.

### P1 — 시간이 되면

- Supabase(DB와 Storage)로 저장소를 옮기고 배포한다. 그러면 공유 링크를 다른 기기에서도 열 수 있다.

### P2 — 나중에

- 앱 안에서 임대인에게 전송하기: 임대인 계정과 로그인, 임차인-임대인 연결이 필요하다. 임대인 계정이 생기면 붙인다.
- 서비스가 이메일이나 문자로 직접 발송하기
- AI가 빠진 정보를 되물으며 정리하는 대화형 작성
- 사진을 AI로 분석해 하자를 표시하기 (WhyTree의 "AI 사진 하자 표시" 노드)

## 범위 밖

- 입주 상태 기록, 퇴거 때 상태 비교
- 수리비 협의와 책임 판단
- 임대인의 답장이나 리포트에 대한 댓글
- 관리사무소 접수 흐름

## AI 모델

- **모델:** Claude Haiku 5.5 (`claude-haiku-5-5`, Anthropic API)
- **입력:** 임차인이 쓴 글. 사진은 보내지 않는다.
- **출력:** 위치, 증상, 처음 발견한 날짜, 현재 영향, 요청 사항을 담은 JSON
- **지시:**
  - 원문에 없는 내용은 쓰지 않는다.
  - 감정 표현, 원인 추정, 책임 주장은 뺀다.
  - 날짜는 원문 표현 그대로 두고 계산하지 않는다.
  - 정보가 없으면 "미입력"으로 둔다.
- **실패 기준:** API 오류, 15초 안에 응답이 없음, 응답이 정해진 JSON 형식이 아님
- **실패하면:** "AI 정리에 실패했어요. 직접 채워주세요"라는 안내를 보여준다. 임차인이 쓴 원문을 "증상" 칸에 넣고 나머지 칸은 "미입력"으로 둔 확인 화면을 띄운다. 임차인은 그대로 고쳐서 보낼 수 있다.
- **AI가 틀리면:** 감정이 남거나 없는 사실을 만들어낸 경우다. 보내기 전에 임차인이 확인 화면에서 직접 고친다.
- **API 키:** `.env`에만 두고, `.env`는 저장소에 올리지 않는다.

## 알려진 한계 (P0 기준)

- 저장소가 로컬이라서 공유 링크는 앱을 실행한 같은 컴퓨터에서만 열린다. 다른 기기에서 여는 것은 P1에서 해결한다.

## 직접 해볼 확인 항목

1. **감정과 책임 추정이 빠지는가**
   - 입력: "아 진짜 짜증나네요 욕실 천장에서 또 물 새요!! 지난주 화요일부터 그랬는데 집주인이 관리를 안 해서 그런 듯. 빨리 고쳐주세요"
   - 기대:
     - 확인 화면에 "짜증나네요", "!!", "관리를 안 해서" 같은 표현이 없다.
     - 위치는 "욕실 천장", 증상은 물이 새는 것, 발견 날짜는 "지난주 화요일", 요청 사항은 수리 요청으로 정리된다.
2. **AI가 실패해도 보낼 수 있는가**
   - 방법: `.env`의 API 키를 일부러 틀린 값으로 바꾸고 1번과 같은 글을 입력한다.
   - 기대: 실패 안내가 나온다. 원문이 "증상" 칸에 들어간 확인 화면이 뜬다. 보내기를 누르면 공유 링크가 생긴다.
3. **임대인이 로그인 없이 보고, 내용이 바뀌지 않는가**
   - 방법: 보낸 리포트의 공유 링크를 시크릿 창에서 연다.
   - 기대: 로그인 요구 없이 5개 항목, 사진, 보낸 시각이 보인다. 수정 버튼이나 입력 칸이 없다.
